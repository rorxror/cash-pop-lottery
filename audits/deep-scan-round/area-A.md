# AREA-A findings — player-facing frontend + post-login behaviour (read-only audit, `~/workspace/cash-pop-fix/`)

[A-01] GALTI — Register error re-render kills the phone country-code dropdown and the referral code, and loses all typed input — routes/auth.js:302-309 — evidence: POST render is `res.render('register', { metaTitle…, formError, otpEnabled…, captchaHtml…, googleOn…, facebookOn… })` with **no `phoneCountries` and no `refCode`**, while GET /register (auth.js:279-280) passes both — impact: after any common validation error (password mismatch, breached password, duplicate email) views/register.ejs:32-34 renders `(typeof phoneCountries !== 'undefined' ? phoneCountries : [])` = an empty `<select>` (only the disabled placeholder), so the phone number can no longer be entered at all; the hidden `ref` input (register.ejs:17) disappears, so a resubmit silently drops the referral (POST reads `req.body.ref`, auth.js:356); and no register input carries a `value=` attribute, so name/email/phone must all be retyped.

[A-02] GALTI — Failed login loses the identifier: `emailPrefill` is passed by every render but never used in the view — routes/auth.js:126 — evidence: render passes `emailPrefill: req.body.email || ''`, but `grep emailPrefill views/` returns nothing and views/login.ejs:56 is `<input type="text" id="pwIdentifier" name="email" … required>` with no `value=` — impact: every failed sign-in (wrong password, captcha fail, TOTP fail) returns a blank identifier field; the prefill plumbing is dead code.

[A-03] GALTI — v19 BP-14 sessions card (and the password card state) vanish/misrender on every POST render of /security — routes/player.js:748, 756, 765, 797 — evidence: GET /security (player.js:714-722) passes `hasPassword, sessions, currentSessionId`, but totp/start, totp/confirm (bad code), totp/confirm (success) and totp/backup all render only `{ totpEnabled, showSetup/showBackup, setup/backupCodes }` — impact: views/security.ejs:91 guards `typeof sessions !== 'undefined'`, so the new Active Sessions card silently disappears exactly on the setup/enable/backup-code screens; and security.ejs:76-80 treats undefined `hasPassword` as "has password", so a passwordless (Google/OTP) account is shown "Change password" with a mandatory Current-password field it can never pass, instead of "Set a password".

[A-04] GALTI — Homepage "Paid out" hero figure is a base-currency DB total formatted with the visitor's *display* currency (no conversion exists) — routes/site.js:60 — evidence: `paid_out_fmt: req.fmt(statPaid)` where `req.fmt` defaults to `req.cur` (server.js context middleware) and statPaid was queried `AND currency = base_currency` (site.js:47); lib/util.js:77-84 `fmtMoney` only relabels (symbol/decimals of the given code, never converts) — the /api/stats twin does it correctly (`req.fmt(paidOut.s, baseCur)`, site.js:31) — impact: a visitor who picks EUR/JPY in the header currency picker sees the USD total wearing a € symbol, or rescaled ×/÷100 for 0-decimal JPY (views/index.ejs:33 also sets `data-symbol` from `cur`, and public/app.js count-up re-formats with that symbol).

[A-05] GALTI — Every page's meta description renders empty — views/layout.ejs:7 — evidence: `<meta name="description" content="<%= S('metaDesc') %>">`; `S()` reads *settings* keys (server.js `res.locals.S`), and no setting named `metaDesc` exists — all routes pass `metaDesc` as a render local (e.g. site.js:57, player.js:259), which the layout never references — impact: homepage/CMS/results descriptions精心 set in routes (and CMS `pg.meta_desc`, site.js:70) never reach the HTML; SEO/social previews are blank site-wide.

[A-06] GALTI — v19 KYC submissions table overflows/clips on mobile — views/kyc.ejs:40 — evidence: `<table class="tbl">` sits directly in `.form-card` with **no `.tbl-wrap` wrapper** (every other player table — wallet, results, tickets, security sessions — is wrapped); public/style.css:409 sets `.tbl { min-width: 560px }` and style.css:104 sets `html, body { overflow-x: hidden/clip }` — impact: on a ≤640px `.narrow` phone layout the 560px table cannot scroll (no wrap) and the page cannot scroll sideways, so the Status column and the "View" document button are cut off/unreachable for exactly the users who must re-submit a rejected document.

[A-07] GALTI — KYC-blocked deposit/withdrawal lands on a dead-end error page with no link to the KYC page — routes/player.js:277, 297, 340, 367 + lib/kyc.js:43-46 + views/error.ejs:4-8 — evidence: block message says *"Please submit your identity document on the KYC page"* but is rendered through `error`, whose only actions are `Back to Home` and `Contact Support`; the same template also prints the heading **"Something went wrong"** for clean 400/403/404s — impact: a BP-21-blocked player is told to go somewhere the page gives them no way to reach, and a routine 403 reads like a server crash.

[A-08] KAMZORI — POST /kyc unconditionally demotes a verified user back to pending — routes/player.js:555 — evidence: `UPDATE users SET kyc_status = 'pending' WHERE id = ?` runs for any accepted upload with no current-status guard; only the *view* hides the form (`kyc.status !== 'verified' && !== 'pending'`, kyc.ejs:24) — impact: a verified player who reaches the POST (second tab, back-button resubmit, direct POST) instantly loses verified status and, where KYC gates withdrawals, re-blocks themselves until staff re-review.

[A-09] KAMZORI — Password-reset email link is a bare relative path when BASE_URL is unset — routes/auth.js:394 — evidence: `const link = (process.env.BASE_URL || '') + '/reset/' + token;` — impact: with BASE_URL missing the email contains `/reset/<token>`, unclickable/unusable; the sibling verify-email flow was already fixed with a host fallback (`process.env.BASE_URL || (req.protocol + '://' + req.get('host'))`, player.js:647), this one was not.

[A-10] KAMZORI — Public contact form: no rate limit, and CSRF is waived for session-less posts — routes/site.js:136 + server.js:298-301 — evidence: `router.post('/contact', …)` has no `rateLimit(...)` (deposit/play/support/auth posts all have one) and GET /contact (site.js:133) never creates an anon session, so submissions arrive session-less, where the CSRF middleware does `if (!req.sess) { if (authPaths.includes…) 403; return next(); }` — impact: unauthenticated, unthrottled inserts into `contact_messages` (staff-queue spam / DB growth) from any origin.

[A-11] KAMZORI — No cache protection on authenticated pages: back-button after logout re-displays cached wallet/profile — server.js (whole file) — evidence: no global `Cache-Control` middleware exists; the only `no-store` sets in the codebase are routes/player.js:568 (KYC document) and routes/admin.js:1908 — impact: logout correctly destroys the server session (auth.js:261-265), but browsers may serve the last wallet/profile/security pages from cache on Back, exposing balances and personal data on a shared device (display-only — actions still fail — hence KAMZORI, not GALTI).

[A-12] KAMZORI — "Tickets today" is actually a rolling 24-hour count — routes/site.js:20 and :46 — evidence: `WHERE created_at > ?` with `Date.now() - 86400000`, rendered under the label "Tickets today" (views/index.ejs:32) in both the page and /api/stats — impact: the displayed number is real but mislabelled; early-morning it mostly counts yesterday's tickets, conflicting with the everything-real presentation rule.

[A-13] GALTI — Homepage displays an invented "Today's lucky number" with no DB/fairness source — views/index.ejs:39-43 — evidence: `const lucky = (new Date().getDate() * 7 + new Date().getMonth() * 3) % 15 + 1;` rendered as *"Today's lucky number is **<%= lucky %>**"* with that ball pre-selected on the Mini Playslip — impact: a fabricated, date-arithmetic number presented to players as a daily fact on a provably-fair lottery site; not a draw result, not a configured product — exactly the invented-display class the everything-real rule bans.

[A-14] GALTI — Hardcoded "Secure & Licensed" trust claim with no configuration or verification gate — views/login.ejs:122 — evidence: `<div class="login-trust">🔒 Secure &amp; Licensed · 18+ only · Play responsibly</div>` is unconditional static text (no setting, no licence field anywhere in the render path) — impact: every visitor is told the operator is licensed regardless of the deployment's actual licence state — a false-claim/genuineness (BP-25) exposure on the sign-in page.

[A-15] KAMZORI — Operator-internal terminology leaked to players in withdrawal success flashes — routes/player.js:433 and :519 — evidence: `'Withdrawal submitted and auto-approved under the auto-withdrawal limit. The payout will follow through the normal payment step.'` — impact: players are told about the operator's BP-22 auto-approval limit machinery ("auto-withdrawal limit", "normal payment step") — admin jargon that invites support questions and discloses internal payout policy mechanics.

[A-16] KAMZORI — Support thread shows staff's raw DB role as the author name — views/support_view.ejs:8 — evidence: `<strong><%= m.mine ? 'You' : m.author_role %></strong>` prints the literal `admin` / `agent` role string — impact: players see internal role codes instead of "Support team"; also makes agent-vs-admin handling visible, which no other player surface does.

[A-17] KAMZORI — Transactions history silently truncates at 200 rows with no pagination or notice — routes/player.js:579 — evidence: `sql += ' ORDER BY created_at DESC LIMIT 200'` and views/transactions.ejs has no pager/"showing latest" note (contrast /tickets and /scratch/my-tickets, paginated in the DS-058 fix) — impact: a long-standing player can never see or verify older ledger entries, including old wins/charges, from the UI.

[A-18] KAMZORI — Money display hardcodes ÷100 / `$` in places the server side correctly derives from currency decimals — views/deposit_new.ejs:32, views/withdraw_new.ejs:25, public/app.js:8 and :120, views/scratch_responsible.ejs:1 — evidence: deposit/withdraw inputs use `min="<%= method.min_amount / 100 %>"` while the server converts with `decimalsFor(method.currency)` (player.js POST handlers) and `fmtMoney` uses `10 ** dec` (util.js:79-82); app.js `fmtMoney` and the hero count-up both divide by 100; the responsible-play pending-decrease line prints a literal `$` — impact: only correct for 2-decimal currencies; with a configured 0-decimal (JPY) or 3-decimal (KWD) currency, min/max attributes, charge/hero animations and the limits notice are off by 10×–100× or carry the wrong symbol (default-USD deployment unaffected).

[A-19] KAMZORI — Wallet KYC card renders as an empty box for a verified user — routes/player.js:257-258 + views/wallet.ejs:2-13 — evidence: `kycNotice` is built whenever `kycSt !== 'none'` (so 'verified' included), but the template only has body branches for blocked / rejected / pending — verified falls through — impact: a verified player sees a headed card ("Identity verification (KYC) — Approved") with no body text at all; profile's equivalent card (profile.ejs) handles this state correctly.

[A-20] SUSPECT — Homepage/API "Recent verified winners" may include test-draw wins — routes/site.js:27 and :53 — evidence: both `recentWins` queries filter only `type IN ('win','scratch_prize')` with no draw/test exclusion, while neighbouring queries explicitly exclude test draws (`is_test = 0`, site.js:43, DS-075) — what would prove it: settle a TEST draw with a ticket entry held by any account and check whether its `win` transaction surfaces in `/api/stats` recentWins / the homepage ticker; if test-draw entries can only ever belong to staff test accounts, impact is staff names/amounts leaking as "verified winners".
